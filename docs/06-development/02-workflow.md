# 协作与开发流程

## 分支与变更

- 远程 `master` 是默认分支，现阶段只保留项目 README。开发文档和后续实现集中在远程 `develop`，本地 `dev` 跟踪它。
- 多人开发时，从最新的 `develop` 建立任务分支，完成后提交面向 `develop` 的 PR。每个变更尽量围绕一个目的，提交说明写清做了什么。
- PR 说明包含变更目的、主要行为变化、关联文档和验证结果。未运行的检查标为未验证；多人协作时，由熟悉相关部分的人评审后合并。

## 开发完成标准

1. 需求或行为有明确的完成条件；实现变化能对应到需求或待解决的问题。
2. 按 [项目协作规则](../../AGENTS.md) 维护当前模块及实际受影响的文档，随本次变更一起更新。
3. 运行与改动相关的检查并记录结果。仅改文档时，核对路径、链接与命令；涉及代码时，验证受影响的行为。
4. 确认变更没有带入本机专用路径、凭据、真实学生资料或构建产物。
