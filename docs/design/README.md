# 系统设计

状态：草稿。待需求范围明确后补充实际设计与图示。

| 设计内容 | 要回答的问题 |
| --- | --- |
| 系统边界与用例图 | 用户和外部系统是谁，各自与系统发生哪些交互？ |
| 组件与职责 | 系统由哪些部分组成，各部分负责什么，依赖如何流动？ |
| 核心类与类图 | 关键对象有哪些，它们的职责、关系和约束是什么？ |
| 关键流程与序列图 | 一次操作怎样完成，跨越哪些组件，发生失败时怎样处理？ |
| 数据与访问控制 | 哪些数据要保存，如何约束和维护，谁可以访问或修改？ |
| 外部依赖与故障处理 | 系统依赖哪些外部能力，超时、失败或不可用时怎么办？ |

图和正文使用相同术语，说明适用场景及关联需求。接口细节写在 [API 手册](../api/README.md)，影响多个部分或不易撤回的选择写进 [技术决策记录](../decisions/README.md)。
