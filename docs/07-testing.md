# 测试与验证

## 运行接口集成检查

先完成[构建](06-development/01-setup.md)，再从仓库根目录在一个终端启动测试实例。`mktemp` 生成独立目录，脚本会写入测试账号、作业和评分，使用真实数据库文件。

```sh
qa_dir=$(mktemp -d)
Storage__DataDirectory="$qa_dir" mise exec -- dotnet run --no-build --project src/HomeworkGrading.Api -- --urls http://127.0.0.1:5081
```

在另一个终端运行：

```sh
BASE_URL=http://127.0.0.1:5081 mise exec -- python scripts/smoke_test.py
```

脚本使用 Python 3.12 标准库，目标为启用演示数据、未配置模型密钥的开发实例。测试结束后可停止实例并删除临时目录。API 契约见[手册](04-api.md)。

## 验证结果

验证环境为 macOS ARM64，mise 选用 .NET SDK 8.0.428。解决方案编译通过，0 警告、0 错误。

| 关联需求 | 实测内容 | 结果 |
| --- | --- | --- |
| REQ-001 | 演示账号登录、注册、退出、错误凭据、匿名访问和角色隔离、跨来源写请求拦截 | 通过 |
| REQ-002、REQ-005 | 发布、修改、删除、分页与汇总、教师和学生的详情投影、响应状态码及 `Location` | 通过 |
| REQ-003 | 学生交作业、截止后拒绝、并发重复提交、删除与提交并发、评分重复保存、服务重启后学生读取原成绩 | 通过 |
| REQ-004 | 模型未配置时返回 `503`，人工批改可继续 | 通过 |

另已构建 Release 发布目录并在本机运行。检查生成的 OpenAPI 定义覆盖 14 个操作，写操作声明必需请求头，错误响应声明 `application/problem+json`。

真实模型服务调用需要独立密钥，本次未运行。

## 前端验收计划

状态：待实现和执行。页面和交互以[前端设计](03-design/02-frontend.md)为准。联调使用独立的演示数据目录和不同浏览器会话，分别登录教师和学生；发布环境也要覆盖同源访问与页面刷新。

| 需求 | 验收场景 | 预期 |
| --- | --- | --- |
| REQ-001、REQ-005 | 学生注册、教师登录；刷新详情及批改页；访问另一角色路由；退出或会话过期。 | 注册和登录后按角色进入，刷新恢复身份；跨角色访问受限，切换账号不显示上个账号的数据。错误凭据留在登录页，退出后受保护页面不可用。 |
| REQ-002、REQ-003 | 教师发布 → 学生提交 → 教师保存 0 分与反馈 → 学生刷新详情；再修改成绩。 | 学生提交前后状态清楚，待批改和 0 分有区别，学生看到最新已保存结果；教师和学生的列表按各自视角更新。 |
| REQ-002、REQ-003 | 教师尝试修改或删除已有提交的作业；打开教师编辑页后让学生先提交；学生在两页重复交卷或跨过截止时间再提交。 | 改删入口与提交入口正确更新；收到冲突后重读详情，按实际状态说明已有提交、已交卷或已截止。 |
| REQ-003、REQ-005 | 让客户端在服务器完成交卷或评分后收不到响应；删除当前列表最后一项或批改后当前筛选页变空。 | 重读服务器状态，再决定是否重试，页面回到有效页；筛选计数和当前页总数各自正确。 |
| REQ-004 | 在测试替身下返回延迟建议、限流或超时；没有评分标准或模型未配置时人工批改。 | 延迟建议不覆盖正在编辑的内容，采用后还要保存；生成失败不影响人工评分。真实模型服务另行联调。 |
| REQ-001 至 REQ-005 | 手机窄屏完成学生交卷与成绩查看，教师使用键盘完成编辑和批改，在部署后的站点直接打开业务页面。 | 操作可达，状态可读，对话框焦点正常；同源会话正常，页面刷新可以进入对应路由，API 错误仍为接口响应。 |
