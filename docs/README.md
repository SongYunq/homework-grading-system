# 项目文档

这里维护从需求讨论到交付所需的项目文档。仓库根目录的 [README](../README.md) 只做项目简介与导航。[课程原始说明](courseware/作业批改-2026.pdf) 保留在 `courseware/`，项目讨论与后续方案写在对应文档中。

| 文档 | 记录什么 | 何时补充或更新 |
| --- | --- | --- |
| [需求说明](requirements/README.md) | 使用场景、范围、业务规则、完成条件 | 需求讨论时；行为或范围变化时 |
| [系统设计](design/README.md) | 系统边界、组件、数据和关键流程；用例图、类图、序列图 | 需求形成后；设计与实现变化时 |
| [API 手册](api/README.md) | 接口契约、错误与调用示例 | 接口设计时；调用方式或行为变化时 |
| [开发环境](development/setup.md) | 工具版本、安装方式、常用命令和排查方法 | 环境或命令变化时 |
| [协作与开发流程](development/workflow.md) | 分支、提交、评审和开发完成标准 | 团队协作方式变化时 |
| [技术决策记录](decisions/README.md) | 技术选择、取舍、依据和重新评估条件 | 形成影响后续开发的决定时 |
| [测试与验证](testing/README.md) | 测试范围、用例、复现步骤和验证结果 | 需求或实现变化时；执行验证后 |
| [发布与交付](release/README.md) | 打包方式、交付清单、版本说明和运行验证 | 形成可运行版本时 |
| [使用手册](usage/README.md) | 如何启动、操作、停止和排查 | 操作步骤或用户可见行为变化时 |

## 维护约定

- 统一使用 Markdown，文件名用简短英文，文档间使用相对链接。篇幅变长时再拆页，并从索引或上级页面链接到新页。
- 用「草稿」「已确认」「已替代」区分文档结论；未决定的内容记为待讨论。测试或平台兼容性只记录实际验证过的结果。
- 每类信息以对应文档为准：需求记业务行为，设计记实现方案，API 手册记调用契约，使用手册记用户操作。需要引用时链接原文，避免多份文档各写一遍。
- 行为、接口、环境或发布方式变化时，在同一个变更中更新相关文档；文档改动也要核对链接、命令和示例。
- 本仓库公开，文档、截图和测试示例统一使用虚构或脱敏数据，不提交凭据和可识别学生的真实作业。

需求讨论开始后，从 [需求说明](requirements/README.md) 记录来源与完成条件。关键方案确认后再补 [系统设计](design/README.md) 和 [技术决策记录](decisions/README.md)，实现时关联 [API 手册](api/README.md) 与 [测试与验证](testing/README.md)。
