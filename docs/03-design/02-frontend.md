# 前端设计

状态：设计草稿。React 与 TDesign 已确认；本稿用于评审页面、交互和接入方案。首版覆盖 [REQ-001 至 REQ-005](../02-requirements.md)，使用[现有 API](../04-api.md)，无需新增接口。

教师工作台、批改页及学生作业页已有[样式预览](../09-usage.md#前端样式预览)，后续接入方案见下文。

## 页面与导航

同一个前端项目提供教师工作台和学生作业页。登录、注册、错误提示和基础组件共用；教师和学生各有自己的布局。教师默认进入「我的作业」，学生默认进入「作业」。

下表中 API 路径相对 `/api/v1`。请求字段和错误定义以 [API 手册](../04-api.md)为准。

| 页面与路由 | 页面安排 | API 与读取时机 |
| --- | --- | --- |
| `/login`、`/register` | 居中的登录或注册表单；登录无需选择角色，注册页注明仅创建学生账号。 | 提交表单调用 `POST /auth/login` 或 `POST /auth/register`；直接使用返回的角色进入相应页面。 |
| `/teacher/assignments` | 「我的作业」页头及发布按钮；状态筛选、作业数量和分页表格。行内展示学科、截止时间、提交数和已批改数；点击标题进入详情。 | `GET /assignments`；切换筛选或页码时用相应查询参数重新读取。 |
| `/teacher/assignments/new`、`/teacher/assignments/:assignmentId/edit` | 共用作业表单。基本信息、题目、参考答案与评分标准分组；说明后两项仅教师可见，填写评分标准才能生成建议。 | 新建 `POST /assignments`；编辑先 `GET /assignments/{assignmentId}`，保存时 `PUT /assignments/{assignmentId}` 发送完整字段。成功进入详情。 |
| `/teacher/assignments/:assignmentId` | 顶部显示作业信息和改删操作；下方是分页提交摘要，每行提供批改或查看入口。删除需确认，成功后返回列表。 | `GET /assignments/{assignmentId}` 支持提交列表分页；删除调用 `DELETE /assignments/{assignmentId}`。 |
| `/teacher/assignments/:assignmentId/submissions/:submissionId` | 左侧对照题目、学生作答及可用的评分依据，右侧填写分数和反馈。保存与模型建议分别呈现；返回作业详情时保留原分页。 | `GET /submissions/{submissionId}` 读取完整作答；已有对应作业详情可复用，否则并行读 `GET /assignments/{assignmentId}` 补满分和评分标准。渲染答卷和允许写入之前校验提交的 `assignmentId` 与路由一致。 |
| `/student/assignments` | 状态筛选与作业卡片；卡片展示学科、截止时间、当前进度，直接进入作业详情。 | `GET /assignments`，和教师列表共用请求代码及分页规则。 |
| `/student/assignments/:assignmentId` | 题目下方依当前状态显示答案编辑区、已交待批改提示或成绩和反馈。 | `GET /assignments/{assignmentId}` 直接提供本人提交及成绩；交作业用 `POST /assignments/{assignmentId}/submissions`。 |

在作业列表的地址中保留 `status`、`page`、`pageSize`，教师作业详情保留提交页码和每页条数。切换筛选或每页条数时回到第一页；返回原页面时恢复筛选和分页。用后端 `totalCount` 驱动分页，用 `summary` 提供各筛选标签的作业数。老师的提交分页没有服务器端批改筛选，也没有全量已批改人数；不要从当前页摘要计算全量统计。首版只呈现接口支持的筛选，班级、附件、重交等范围见[需求说明](../02-requirements.md)。

## 布局与组件

| 区域 | 布局和组件 |
| --- | --- |
| 教师端 | 顶部栏放姓名和退出，侧边放工作台入口。使用 TDesign `Table`、`Pagination`、`Tag` 显示作业与提交；用 `Form`、`DatePicker`、`InputNumber`、`Textarea` 完成发布与评分。 |
| 学生端 | 简洁顶栏，作业列表使用 `Card`，窄屏为单列。详情先显示题目、截止时间和状态，再显示答案或结果，主操作紧挨对应表单。 |
| 共用反馈 | 初次加载、没有任何数据、筛选无结果、读取失败分别提供可读提示；读取失败可重试。校验提示放在字段旁，冲突和模型故障放在对应区域。删除、交卷和覆盖已有评分草稿用 `Dialog` 确认。 |

教师批改页在窄屏按「题目和作答 → 评分」纵向排列；提交列表收起次要列或改用摘要卡片，保留查看和批改入口。状态标签同时给文字和颜色。交互需支持键盘访问、可见焦点、表单标签和对话框关闭后焦点归还。题目、作答、评语和模型建议按纯文本显示并保留换行。

两个核心页面的信息顺序如下：

```text
教师 · 批改作答                         学生 · 作业详情
‹ 返回提交列表                          ‹ 返回作业列表
作业标题 · 学生姓名 · 提交时间          作业标题 · 学科
题目和作答        │ 评分 / 满分         截止时间 · 满分 · 个人状态
评分标准、参考答案 │ 反馈                题目
                  │ [保存评分]          答案填写 / 已交答案与成绩
                  │ 评分建议 · 生成/采用 [确认提交]（仅可提交时）
```

## 作业与批改状态

**截止时间与提交进度分开显示。** 列表用接口的 `status` 展示及筛选进度；能否接收提交根据 `dueAt` 判断，已批改也可能尚未截止。发布表单按浏览器本地时间填写并标注当前时区，提交时转换为有时区的时间字符串，页面采用同一显示规则。学生提交前结合 `dueAt` 和 `mySubmission` 提供按钮状态；页面跨过截止时间后更新提示，最终以后端校验为准。

| 场景 | 界面与数据处理 |
| --- | --- |
| 教师修改或删除 | 以当前作业详情的 `submissions.totalCount` 判断，已有提交则改删不可用并说明原因。零提交的已截止作业仍可编辑，保存时需给出新的未来截止时间。若打开编辑后有学生先提交，收到 `assignment_has_submissions` 后重读详情，将编辑切为不可保存状态。 |
| 学生首次交作业 | 提交前确认只能交一次；发送期间禁用重复点击。成功后用响应更新详情为已提交，并使列表失效。无响应时先重读详情确认是否已收到；遇到 `submission_already_exists` 或 `assignment_closed` 同样重读，以实际提交或截止状态显示，避免误报成功。失败时尽量保留当页输入。 |
| 学生查看成绩 | 没有 `mySubmission` 表示未交。有提交且 `score === null` 显示待批改；有有效数字（包括 `0`）显示分数、满分和评语。返回详情、重新聚焦页面或点击刷新时可重新读取；无需轮询。 |
| 教师保存或更新评分 | 调用 `PUT /submissions/{submissionId}/grade`。成功后用返回值刷新已保存成绩和表单基线，使相关作业详情与列表失效。失败保留编辑内容；网络结果不明确时，重新读取该提交核对已保存成绩，再由教师决定是否重试。 |

### 模型建议

有评分标准时才启用「生成建议」，需要教师主动点击。用 `POST /submissions/{submissionId}/grade-suggestions` 发起一次请求；独立显示等待状态，在建议返回前仍可填写、保存人工评分。返回后在独立区域预览建议，点击「采用建议」才填入评分表单；若已有未保存的人工内容，先确认覆盖。建议本身不发布成绩，仍需教师点击「保存评分」。

建议按当前账号和提交隔离。离开页面、切换账号或提交、保存正式评分后，取消或忽略过期建议，防止迟到的响应回填。没有评分标准时就地说明；模型不可用、超时或限流只影响建议区域。前端不以探测请求判断模型是否配置，也不直接调用模型服务。

## 会话与请求

遵循[同源会话决策](../05-decisions.md#d-003--浏览器会话)及[浏览器接入约定](../04-api.md#浏览器接入)。请求层统一发送相对路径，写请求带固定请求头，按响应类型解析；`204` 不读正文。字段空值或缺失按契约处理，分数和满分按 JSON 数字发送，密码原样提交。

- 进入需要身份的页面且账号未知时，发起一次 `GET /auth/me`，等待身份确定后再读角色数据。身份读取因网络或服务错误失败时显示可重试状态。登录和注册已经返回身份时直接复用，不在每个业务请求前检查。退出使用 `POST /auth/logout`；成功或收到未登录响应后清除当前账号的页面数据，网络失败时提示退出未确认。
- 前端根据角色选择导航和页面布局，后端校验实际访问权限和资源归属。登录的 `invalid_credentials` 留在表单；业务请求的 `401` 结束当前会话并回登录。登录后仅回到同角色允许的站内路径，否则进入角色首页；`403` 展示无权操作，`404` 统一提示找不到资源或不可查看。
- 按请求动作、状态码和 `code` 处理错误。绑定错误按 `errors` 定位字段，已知业务校验码关联字段，其他问题在当前操作区显示。限流优先按 `Retry-After` 提示。区分模型不可用和普通接口暂不可用；代理错误或无 JSON 响应时显示通用请求失败提示。
- 写操作等待后端确认再更新界面，不自动重试。发布结果不明时保留表单，引导教师先查看作业列表，避免重复发布。分页数据失效后如果原页超出范围，回到最后一个有效页；无数据则回到第一页。

## 代码与数据职责

建议在同仓库新增 `src/HomeworkGrading.Web/`，首版采用浏览器渲染。技术选型见 [D-005](../05-decisions.md#d-005--react-前端与组件库)。

| 拟设目录 | 职责 |
| --- | --- |
| `src/app/` | 路由、角色布局、账号会话、全局组件配置。 |
| `src/features/auth/` | 登录、注册、退出表单和身份相关请求。 |
| `src/features/assignments/` | 教师和学生的列表与详情、发布和编辑表单、有效期限与状态展示。 |
| `src/features/submissions/` | 文本提交、教师批改、模型建议和学生结果展示。 |
| `src/shared/` | 共用请求入口、错误解析、时间格式和跨页面复用的展示组件。 |

React Router 负责页面导航和地址参数，TanStack Query 负责后端数据的读取、取消与更新。表单草稿由当前页面管理，后台读取不覆盖编辑中的字段。账号信息和请求数据只保存在内存，请求缓存按账号区分，并在退出、会话失效和切换账号时取消旧读取、清除旧数据；旧请求结果不得写入新会话。任何作答或评分内容都不进入地址或浏览器持久存储。依赖参考：[路由](https://reactrouter.com/start/declarative/routing)、[请求取消](https://tanstack.com/query/latest/docs/framework/react/guides/query-cancellation)、[保存后的数据刷新](https://tanstack.com/query/latest/docs/framework/react/guides/invalidations-from-mutations)。

本地开发由 [Vite 转发 `/api`](https://vite.dev/config/server-options#server-proxy)到 .NET；部署时由同一 HTTPS 入口提供前端构建产物并转发 API。部署配置先匹配 `/api` 与探活路径 `/health`；已知前端页面的直接访问或刷新回退到前端入口，资源文件缺失正常返回错误。

建议先接通登录和教师发布、学生提交、人工批改、学生查看的完整流程，再补模型建议及并发冲突、窄屏和键盘操作。具体检查见[前端验收计划](../07-testing.md#前端验收计划)。
